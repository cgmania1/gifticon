## 결정과 이유

- **실제 사진은 커밋하지 않음.** 기프티콘은 결제 수단이고 캡처에 휴대폰 알림·상태 표시줄이 담깁니다. 읽은 줄의 글자만 테스트에 넣고(상태 표시줄 줄은 시각만 남김), 회귀용으로는 흉내 낸 그림을 새로 그렸습니다.
- **두 번째 읽기는 발행처가 없을 때만.** 휴대폰에서는 한 번 읽는 데 몇 초 걸려, 늘 두 번 읽으면 기다림이 두 배가 됩니다. 두 번째 읽기 그림은 다른 줄(수량/금액 등)을 오히려 놓치기도 해서(실측) 발행처 찾기에만 씁니다.
- **색 배경 지우기는 「밝은 채널」 방식.** 회색 변환·확대·이진화도 재 봤는데, 확대는 상품명을 깨뜨리고(「이마트」→「OIDIE」), 이진화는 날짜를 틀리게 읽었습니다(09.30 → 09.20). R·G·B 중 밝은 값을 쓰면 검은 글씨는 그대로, 파랑·분홍 배경만 하얘집니다.
- **브랜드 목록은 짧게, 추측은 경고로.** 흐린 브랜드 글씨는 규칙으로 되살릴 수 없어(「메가\(9ㄷ커피」·「메기1ㄴ커피」) 목록으로 바로잡습니다. 흔한 32곳만 두고, 목록으로 넣은 발행처는 「확인해 주세요」가 뜹니다. 「사용처」 라벨이 있으면 라벨이 먼저입니다.
- **「5만원」 뒤 「권」 붙이기**는 금액을 읽었고 상품명이 「…원」으로 끝날 때만. 줄 가운데 금액(「치킨 3만원 세트」)·「4,500원」은 금액으로 보지 않습니다.

## 결정과 이유

- **자동 발송이 아니라 「보내기」 버튼.** 브라우저는 앱이 닫혀 있을 때 스스로 카톡·문자를 보낼 수 없고, 열려 있어도 사람의 확인 없이 문자를 보낼 수 없습니다. 휴대폰의 공유 창·문자 앱에 글을 넘기는 것까지가 무료로 할 수 있는 최대입니다. 정해진 시각 자동 발송은 유료 발송 대행 + 서버(2단계).
- **카카오 JS SDK 를 쓰지 않음.** 카카오톡 공유 API 는 무료지만 카카오 개발자 앱 키(JavaScript 키)를 코드에 넣고 사이트 도메인을 등록해야 합니다. 공개 리포에 키를 두지 않는다는 원칙과 맞지 않고, 공유 창으로 같은 결과(카카오톡 → 대화방 고르기)를 얻습니다.
- **문자 번호는 기기에만.** DB 에 칸을 늘리면 스키마·RLS·하네스를 다 고쳐야 하고, 번호는 보내는 사람의 휴대폰에만 있으면 됩니다. 수강생 확인 「한 가족만」이라 보내는 사람이 한두 명이어서 기기별 입력도 부담이 작습니다.
- **`sms:` 본문 붙이는 법이 휴대폰마다 다름** — 안드로이드 `?body=`, 아이폰 `&body=`(여러 명이면 `sms:/open?addresses=`). 사용자 에이전트로 고릅니다(아이패드 데스크톱 모드는 터치 지점 수로 구분).
- **보낼 글에 바코드·메모·사진을 넣지 않음.** 상품명·발행처·D-day·유효기간·잔액·예약자만. 메모는 가족 안에서만 보려고 적었을 수 있어서입니다.
- **OCR 은 누를 때만 받음.** 엔진·데이터가 약 8.5MB 라 페이지 열 때 받지 않습니다(네트워크 요청 0건 확인). 엔진 3종(relaxed SIMD·SIMD·기본)을 모두 두고 Tesseract 가 기기에 맞는 하나만 받습니다. 한국어·영어는 `best_int`(정확도판의 정수형, 한국어 1.5MB)를 씁니다.
- **상품명은 가장 큰 글자 줄.** 처음엔 글자 수로 골랐더니 「선물함」 같은 앱 머리글이 뽑혔습니다. Tesseract 의 줄 높이를 받아 가장 큰 글자를 고르고, 머리글·날짜·「10,000원권」 줄·확신도 60 미만 줄을 빼니 가짜 그림 7장 중 6장이 맞았습니다. 추측한 칸은 화면에 경고로 알립니다.
- **바코드 번호는 어디에도 남기지 않음.** 숫자 10자리 이상 줄·「바코드/쿠폰번호/주문번호」 줄은 나누기 전에 버리고, 「읽은 글자 보기」에서도 `****` 로 가립니다. 사진 원본은 OCR 에만 쓰고 저장하는 것은 종전대로 줄인 JPEG 입니다.
- **file:// 는 안 됨(실측).** Chromium 이 file:// 스크립트로 Web Worker 를 만드는 것을 막습니다(`Failed to construct 'Worker' … origin 'null'`). 우회(엔진을 메인 스레드에서 돌리기 등)는 Tesseract.js 가 지원하지 않아, file:// 에서는 안내 문구를 띄우고 방법 2(무료 AI 채팅)를 권합니다.

- **기록은 덧붙이기만.** `giftcon_log` 는 트리거(정의자 권한)만 쓰고, 사용자에게는 읽기 정책만 있습니다(넣기·고치기·지우기 정책 없음). 기프티콘을 지워도 그때의 상품명과 함께 「삭제」 기록이 남습니다.
- **판정 함수 `is_family_member` 는 security definer + `search_path = public`.** 구성원 표의 정책이 구성원 표를 다시 읽는 무한 반복을 끊기 위함입니다. RLS 가 부르므로 authenticated EXECUTE 는 남기고 PUBLIC·anon 은 걷었습니다.
- **가족 만들기·들어가기는 RPC 로만.** 가족·구성원 표에 직접 넣는 정책이 없습니다. 초대 코드는 헷갈리는 글자(0·1·I·O)를 뺀 8자리, 소문자·하이픈을 섞어 적어도 찾습니다. 구성원은 칸 권한으로 표시 이름만 고칠 수 있습니다(가족 옮기기·owner 되기 차단).
- **예약자는 같은 가족만** — `(family_id, reserved_by)` 복합 외래키. 구성원이 나가면 `on delete set null (reserved_by)` 로 예약만 풀립니다(PostgreSQL 15 이상 문법, Supabase 는 15 이상).
- **사진은 비공개 버킷 `giftcons`**, 경로 첫 칸이 가족 id. 정책은 같은 가족만 읽고 올리고 지웁니다. 앱은 긴 변 1280px JPEG 로 줄여 올리고(체험 모드는 900px, localStorage 용량 때문), 볼 때는 1시간짜리 서명 URL 을 씁니다.
- **한눈에 보기** — 요약 4칸이 곧 거르기 단추(사용 가능 = 쓸 수 있는 전부, 7일 이내 만료 = 그중 곧 만료). 카드는 유효기간 빠른 순, 큰 D-day 배지 + 「곧 만료 · 3일 남음」 같은 글자(색만으로 구분하지 않음). 유효기간 당일은 「D-DAY · 오늘까지 사용」, 다음 날부터 만료입니다.
- **알림은 앱 안에서만.** 알림 시점(기본 D-7·D-1)은 기기별 설정. 카카오톡·문자 발송은 유료 발송 대행과 서버(예약 실행 Edge Function)가 필요해 2단계로 미뤘습니다.
- **사진 자동 읽기는 2단계.** 간결함을 위해 반자동 AI 프롬프트 방식도 넣지 않았습니다. 등록 화면에서 사진 미리보기를 보며 칸을 채웁니다.
